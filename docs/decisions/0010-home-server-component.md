# 0010. 홈은 서버 컴포넌트, localStorage를 읽는 부분만 클라이언트로

- 상태: 채택
- 날짜: 2026-10-07
- 근거: [#9 홈 랜딩](https://github.com/imsoohyeok/LOAPI/pull/9)
- 관련 파일: `app/page.tsx`, `components/TrackedCharacters.tsx`, `lib/features.ts`, `components/Navbar.tsx`

## 문제

`/`는 비교 페이지를 그대로 복사해 둔 `"use client"` 페이지였습니다. 홈을 기능 소개 카드와 "최근
기록한 캐릭터" 목록으로 바꾸려는데, 두 부분의 성격이 다릅니다.

- 기능 카드: 모든 사용자에게 같은 정적인 내용입니다.
- 최근 기록한 캐릭터: 브라우저 localStorage를 읽어야 해서 서버에서는 알 수 없습니다.

또 내비게이션과 홈 카드가 같은 페이지 목록을 각자 들고 있으면, 페이지를 추가할 때 한쪽을 빠뜨리기
쉽습니다.

## 고려한 대안

1. **페이지 전체를 클라이언트 컴포넌트로 둔다.** 기존 방식입니다. 정적인 카드까지 클라이언트 번들에
   들어가고 하이드레이션 대상이 됩니다.
2. **페이지는 서버 컴포넌트로 두고, localStorage가 필요한 부분만 클라이언트 컴포넌트로 분리한다.** (채택)

## 결정과 이유

- `app/page.tsx`에서 `"use client"`를 없애 정적으로 렌더링하고, `TrackedCharacters`만 클라이언트
  컴포넌트로 둡니다. 클라이언트 경계를 가능한 한 잎(leaf) 쪽으로 내리는 App Router의 기본 원칙을
  따랐습니다.
- `TrackedCharacters`는 서버에 localStorage가 없으므로 첫 렌더를 자리표시자로 맞춰 하이드레이션
  불일치를 피합니다. #11에서 이 읽기를 `useSyncExternalStore` 구독으로 바꿨습니다
  ([0005](./0005-localstorage-external-store.md)).
- 페이지 목록(경로·이름·설명)을 `lib/features.ts` 한곳에 두고 `Navbar`와 홈 카드가 같이 씁니다.
  실제로 #12에서 거래소를 추가할 때 이 목록 한 곳만 고쳐서 내비게이션과 홈에 함께 나타났습니다.

## 트레이드오프

- 최근 기록 목록은 첫 화면에서 잠깐 자리표시자로 보였다가 채워집니다. 서버가 알 수 없는 데이터라서
  피할 수 없고, 그동안 높이를 잡아 둔 빈 상자를 보여줘서 레이아웃 이동을 줄였습니다.
- 서버/클라이언트 경계가 생겨서, 홈에 상호작용을 더할 때마다 "이 부분을 클라이언트로 내려야
  하는가"를 판단해야 합니다.
