# 0006. 트래커 백업은 버전 있는 파일 + 덮어쓰지 않는 병합으로

- 상태: 채택
- 날짜: 2026-10-07
- 근거: [#13 트래커 기록 백업·복원](https://github.com/imsoohyeok/LOAPI/pull/13)
- 관련 파일: `lib/trackerBackup.ts`, `lib/storage.ts`(`writeSnapshotsBulk`), `lib/file.ts`, `components/TrackerBackup.tsx`

## 문제

트래커 기록은 브라우저 localStorage에만 있어서([0005](./0005-localstorage-external-store.md)) 다른
기기나 브라우저로 옮길 수 없고, 사이트 데이터를 지우면 사라집니다. 서버 저장소를 두지 않는다는
결정은 유지하면서 기록을 옮길 방법이 필요했습니다.

불러오는 파일은 사용자가 고른 **임의의 파일**이라는 점이 핵심입니다. 다른 JSON일 수도, 손으로
고친 파일일 수도, 더 새 버전의 사이트에서 만든 파일일 수도 있습니다.

## 고려한 대안

**파일 형식**

1. localStorage 내용을 그대로 덤프한다. 형식이 내부 키 이름에 묶이고, 이 앱의 파일인지 알 수 없습니다.
2. `kind`, `version` 필드가 있는 전용 형식을 만든다. (채택)

**불러오기 방식**

1. 기존 기록을 지우고 파일 내용으로 **덮어쓴다.** 오래된 백업을 실수로 불러오면 최근 기록을 잃습니다.
2. 같은 날짜가 겹치면 **파일 쪽을 우선**한다. 같은 이유로 최신 기록이 옛 값으로 바뀔 수 있습니다.
3. 기존 기록은 그대로 두고 **없는 날짜만 더한다.** (채택)

## 결정과 이유

- **형식에 정체성과 버전을 적습니다.** `kind: "lostark-tracker-backup"`과 `version: 1`을 먼저 따로
  읽어서, "트래커 백업 파일이 아니에요"와 "더 새 버전에서 만든 백업이에요"를 구분해 안내합니다.
  형식이 바뀌면 버전을 올리고 버전별로 변환하면 됩니다.
- **타입 단언 대신 zod로 검증합니다.** 파일 내용을 `as TrackerBackup`으로 믿지 않고 스키마를 통과한
  값만 씁니다. 날짜는 형식(`YYYY-MM-DD`)뿐 아니라 `2026-02-30`처럼 존재하지 않는 날짜도 막고,
  아이템레벨은 양수, 캐릭터명은 앞뒤 공백 없는 40자 이내로 제한합니다. 모르는 필드는 버립니다.
- **병합은 기존 기록 우선입니다(`planImport`).** 같은 날짜가 있으면 이 기기의 기록을 남기고 없는
  날짜만 추가합니다. 실수로 오래된 백업을 불러와도 잃는 것이 없고, 같은 파일을 두 번 불러와도 결과가
  같습니다(멱등).
- **계획과 적용을 나눴습니다.** `planImport`는 무엇을 쓸지와 추가·건너뛴 개수만 계산하는 순수
  함수이고, 기존 기록을 읽는 함수를 인자로 받아서 localStorage 없이 테스트합니다. 실제 쓰기는
  `applyImport`가 합니다.
- **일괄 쓰기는 전부 아니면 전무입니다(`writeSnapshotsBulk`).** 여러 캐릭터를 쓰다가 저장 공간
  부족 등으로 도중에 실패하면, 이미 쓴 키를 이전 값으로 되돌리고 오류를 다시 던집니다. 절반만
  복원된 상태가 남지 않습니다. 성공하면 구독자에게 **한 번만** 알려서 화면이 캐릭터 수만큼 다시
  그려지지 않습니다.
- 1MB를 넘는 파일은 읽기 전에 거절합니다. 수십 캐릭터 × 수년 치 기록도 수백 KB를 넘지 않는데, 실수로
  큰 파일을 고르면 파싱하는 동안 화면이 멈추기 때문입니다.

## 트레이드오프

- 병합 방식이라서 **기록을 지우는 용도로는 쓸 수 없습니다.** 이 기기의 잘못된 기록을 백업 값으로
  고치려면 먼저 지운 뒤 불러와야 합니다. 데이터를 잃지 않는 쪽을 우선했습니다.
- 롤백은 localStorage 안에서의 원자성만 보장합니다. 다른 탭이 같은 순간에 쓰는 경우까지 막지는
  않습니다. 단일 사용자의 브라우저라는 사용 환경에서 감수할 만하다고 봤습니다.
